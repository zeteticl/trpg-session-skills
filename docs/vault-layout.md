# Vault Layout

All skills operate on a **Vault Root** (path given by the GM or `TRPG_VAULT_ROOT`).

Published site routes (Astro) are documented in [plan-alignment.md](./plan-alignment.md).

```
<vault>/
  INDEX.md
  modules/
    <module-id>/
      module.yaml                 # id, system, title, locales
      source/
        scenario.zh-Hant.md
        scenario.en.md            # optional
      glossary.yaml               # localize owns
      prep/                       # analyze owns (see file list below)
      assets/
        prompts/                  # handout-art owns Prompt Packs
        portraits/
        backdrops/
        handouts/
        tokens/                   # token script output
  campaigns/
    <campaign-id>/
      campaign.yaml
      pcs/                        # character pages for Hub
        <pc-id>.yaml
      hub/                        # campaign-hub owns aggregates
        hub-manifest.yaml         # regenerated by archive sync
        clue-board.md             # regenerated from sessions
      sessions/
        <nnn>/
          session.yaml
          notes.md                # GM Session Notes (required for recap)
          transcript.md           # optional (transcribe)
          live-aid.md             # live-aid owns
          bgm-cues.yaml           # bgm-cue-list/v1
          handout-reveals.yaml    # handout-reveal/v1
          recap.md                # recap owns
          unresolved-clues.md
          keep-appendix.md        # NEVER published
          archive-manifest.yaml   # archive-manifest/v1
          media/
      modules-embedded/           # Embedded Module (same shape as modules/<id>/)
```

## prep/ files (analyze owns)

`00-overview.md` … `15-special-systems.md` — see `trpg-scenario-analyze` / charter §3.

## Embedded Module

Same package shape as `modules/<id>/`, living under `campaigns/<id>/modules-embedded/<id>/`.
